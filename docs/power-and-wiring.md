# 電源・発熱・配線

## 結論

Game Boy Pocketのリンクポート1番からXIAO ESP32S3 Sense本体へ給電しない。XIAOはUSB 5 VまたはBAT端子の1セルLiPoから独立給電する。電源付き5 V/3.3 VレベルシフタをLiPo環境で使う場合に限り、1番の5 VをシフタのHV/VCCB電源だけへ使える。

推奨電源は次のどちらか。

- USB 5 V、連続1 A以上の電源またはモバイルバッテリー
- XIAOのBAT端子へ接続する3.7 Vの保護回路付き1セルLiPo。放電能力は連続1 A以上を選ぶ

USBの5 VとGame Boyリンクポート1番を同じ電源線へ直結しない。シフタのHV/VCCBを1番から取る場合、その配線をXIAOの5V/VBUSへ接続しない。

## 分解した通信ケーブルの判別

通信にはSOUT、SIN、SCKの3信号と共通GNDが必要なので、信号経路として使う導体は合計4本。電源付きレベルシフタのHVをGBから取る場合は、端子1のVCCを加えた合計5本を使う。色だけでは判定せず、Game BoyとXIAOの電源を外した状態で、テスターの導通モードを使ってプラグ端子と各導体の対応を確認する。

Game Boy本体ソケットを外側から見て、平らな側を上にした端子配置は次のとおり。

```text
本体ソケット正面:     ケーブルのプラグ接点面:
上段  2  4  6         上段  6  4  2
下段  1  3  5         下段  5  3  1
```

プラグを背面や配線側から見ると再び左右が逆になる。向きの取り違えを避けるため、番号は目安とし、最終的にはテスターの導通結果で決定する。

使用する端子は次の4本。

| GB端子 | 信号 | 接続先 |
|---:|---|---|
| 2 | SOUT | レベル変換を介してXIAO D1 / GPIO2 |
| 3 | SIN | レベル変換を介してXIAO D3 / GPIO4 |
| 5 | SCK | レベル変換を介してXIAO D0 / GPIO1 |
| 6 | GND | XIAOとレベルシフタのGND |
| 1 | VCC | 電源付きシフタのHV/VCCBだけに使用可 |

端子1のVCCはXIAO本体の給電に使わない。電源不要の受動変換回路や別の5 Vでシフタを動かす場合は端子1を絶縁する。端子4は未使用なので絶縁する。裸の銅線はケーブルのシールド用ドレイン線である可能性があり、端子6との導通を確認できない限りGNDとして使わない。端子6につながる色付き導体がある場合は、その絶縁された導体をGNDに使い、裸線は短絡しないよう絶縁する。

### 電源付きレベルシフタの必須配線

LiPoだけでXIAOを動かす場合、XIAOの5V/VBUS端子から5 Vは生成されない。LV/HV表記のあるレベルシフタは、信号3本だけをつないでも動作しない。次をすべて接続する。

```text
XIAO 3V3       -> LV / VCCA
GB端子1 +5V    -> HV / VCCB
XIAO GND       -> シフタGND -> GB端子6 GND
GB端子2 SOUT   -> HV側信号 ─ LV側信号 -> XIAO D1
GB端子5 SCK    -> HV側信号 ─ LV側信号 -> XIAO D0
XIAO D3        -> LV側信号 ─ HV側信号 -> GB端子3 SIN
```

`OE`端子がある製品は、そのモジュールのデータシートに従って有効レベルへ固定する。一般にVCCA側ロジックで制御するため、単純にHVへつながない。モジュール名が分からない場合は、基板の表面印字と型番を確認してから配線する。

### 今回使用している青色4チャンネル基板

再送された正常な写真でシルクを確認した。写真と同じ向きでは、各側の6端子は次の順序。

```text
H側（上から）: HV4, HV3, GND, HV, HV2, HV1
L側（上から）: LV4, LV3, GND, LV, LV2, LV1
```

今回の正しい接続は次のとおり。

| 位置 | H側 | L側 | 用途 |
|---:|---|---|---|
| 1 | GB 5 | XIAO D0 | SCK |
| 2 | GB 4（外してもよい） | 未接続 | チャンネル3は不使用 |
| 3 | GB 6 | XIAO GND | 共通GND |
| 4 | GB 1 | XIAO 3V3 | HV=5 V、LV=3.3 V電源 |
| 5 | GB 3 | XIAO D3 | SIN |
| 6 | GB 2 | XIAO D1 | SOUT |

すなわち配列表記は次になる。

```text
H側: 5, 4, 6, 1, 3, 2
L側: D0, 未接続, GND, 3V3, D3, D1
```

写真のH側`5, 4, 6, 1, 3, 2`と、L側のD0、GND、D3、D1は正しい。現在不足しているのは、L側の上から4番目にある`LV`電源へのXIAO 3V3だけ。この1本を追加しないと低電圧側のプルアップ電源がなく、信号変換できない。GB端子4とHV3は機能上不要なので、現状のまま相手側LV3を未接続にするか、GB4の線を外して個別に絶縁する。

3V3追加後に、GB側が長時間待ってから会話へ戻る一方、XIAOのLEDが待機表示のままなら、GBはXIAOの`06`を受信できているが、XIAOはGBの`43`を認識できていない。この場合、SCKのチャンネル4とSINのチャンネル2は動作しており、SOUTのチャンネル1だけが故障・接触不良の候補になる。

電源を切ってから、未使用のチャンネル3へSOUT経路を移すと切り分けられる。

```text
変更前: GB端子2 -> HV1 / LV1 -> XIAO D1
変更後: GB端子2 -> HV3 / LV3 -> XIAO D1
```

写真と同じ向きでの変更後の並びは次のとおり。GB端子4は外して絶縁する。

```text
H側: 5, 2, 6, 1, 3, 未接続
L側: D0, D1, GND, 3V3, D3, 未接続
```

移動前にテスターを使う場合、両機器の電源ON・シリアル待機時にHV1-GNDが約5 V、LV1-GNDが約3.3 Vか確認する。HV1が約5 VなのにLV1が約3.3 Vにならない場合は、チャンネル1またははんだ付けの不良である。

### DSO-TC3による実機切り分け

DSO-TC3は10 MS/s、500 kHz帯域なので、Pocketの約8.2 kHzリンククロックを確認できる。最初に導通、次に電圧、最後に波形の順で調べる。

導通試験ではGame Boy、XIAO、DSO-TC3のUSBをすべて外し、LiPoもOFFにする。次の導通を確認する。

- GB端子2とHV1だけが導通する。
- GB端子3とHV2だけが導通する。
- GB端子5とHV4だけが導通する。
- GB端子2と3、HV1とHV2、LV1とLV2の各組は導通しない。

波形測定時はDSO-TC3を内蔵電池で動作させ、USB充電・PC接続を外す。プローブのGNDクリップは回路の共通GND、すなわちGB端子6、シフタGND、XIAO GNDのいずれか一点だけへ接続する。信号端子へGNDクリップを接続しない。

初期設定はDC結合、プローブと本体表示をともに1X、2 V/div、100 us/div、立上りエッジ、トリガレベル約2 Vを目安にする。AUTOで波形を確認した後、先頭バイトを見る場合はSINGLEを使用する。クロック1周期を拡大する場合は50 us/divへ変更する。

| 測定点 | 正常時の目安 |
|---|---|
| HV4 / SCK | 約0～5 V、約8.2 kHzの8クロック列 |
| LV4 / D0 | 約0～3.3 V、HV4と同じタイミング |
| HV2 / GB SIN | XIAOが返す`06`のビット列 |
| LV2 / D3 | 約0～3.3 V、HV2と同じ`06` |
| HV1 / GB SOUT | 最初だけ`43`、ポーリング中は`00` |
| LV1 / D1 | HV1と同じ内容を約0～3.3 Vで表示 |

現在の故障状態ではXIAOがD1から毎回`06`を受信している。LV1とLV2で同じ`06`波形が見え、電源OFF時にも両者が導通するなら短絡で確定する。LV1とLV2が導通しないのにLV1が`06`になる場合は、HV側またはケーブル端子2・3の対応を再確認する。

2026-09-17の実機では、LV1へはんだ付けしたより線の素線1本がLV2へはみ出して短絡していた。素線を処理した後、Geminiの講評をGame Boyへ正常表示できた。より線は予備はんだ後に長さを切りそろえ、隣接パッド間を拡大確認し、電源投入前に導通試験する。

Pan Docsに記載された標準的な色は端子2が赤、端子3が橙、端子5が緑、端子6が青だが、非純正ケーブルや製造ロットでは一致しない。今回の茶・緑・白・赤・黄・青という構成も、テスターで確認するまで色から決定しない。

## 携帯用電池の選択

携帯運用には、XIAOのBAT端子へ接続する保護回路付き1セルLiPoを使う。購入時は公称3.7 V、容量500 mAh以上、連続放電1 A以上を確認する。500 mAhセルなら2 C以上の放電仕様に相当する。実用上は800～1,000 mAhを選ぶと余裕がある。XIAO ESP32S3 Senseの内蔵充電電流は公称100 mAなので、空に近い状態からの充電は500 mAhで少なくとも約5時間、1,000 mAhで少なくとも約10時間かかり、終盤の定電圧充電を含めるとさらに長くなる。

容量だけの理想計算では、電池動作時のWebカメラ平均155 mAに対し、500 mAhは約3.2時間、1,000 mAhは約6.5時間の連続動作に相当する。変換損失、電池の保護回路、温度、経年劣化を見込み、使用可能容量を80%として計画すると、それぞれ約2.6時間、約5.2時間が保守的な目安になる。このファームウェアは撮影の合間にカメラとWi-Fiを停止するため、実際の運用時間は撮影間隔により長くなるが、現在は電流計で待機電流を測っていないため保証値にはしない。

数分間に最大15回ほど撮影する技術デモに限れば、150～200 mAhへ小型化できる。1回の撮影・API通信を30秒として15回行う場合、平均155 mAから求めた消費は約19 mAh。1回60秒でも約39 mAhである。待機、電池の電圧低下、温度、通信再試行を含めても、正常な150 mAhセルなら容量には余裕がある。

小容量セルでは容量より放電性能と充電条件を優先する。150 mAhなら連続放電0.8 A以上、できれば1 A以上、保護回路の過電流遮断値が0.7 Aを超える製品を選ぶ。XIAOの撮影ピーク366 mAは約2.4 C、カメラ表の最大0.6 Aは4 Cに相当する。200 mAhならそれぞれ約1.8 C、3 Cになる。100 mAhでも容量計算上は足りるが、366 mAで約3.7 C、最大0.6 Aで6 Cとなり、保護回路付きの小型セルでは条件を満たしにくい。

XIAO Senseの内蔵充電電流は100 mA。150 mAhセルでは約0.67 C、100 mAhセルでは1 Cになるため、セルのデータシートに100 mA以上の充電許容値が明記された製品だけをXIAOから充電する。100 mAh未満は充電電流が過大になりやすいため、内蔵充電器をそのまま使う構成には採用しない。デモ運用では電池とBAT端子の間に電源スイッチを入れ、使用直前にON、終了後にOFFにすると待機消費を確実に止められる。

CR2032などのボタン電池は使用しない。代表的なCR2032は公称容量225 mAhでも標準連続放電は0.2 mAであり、XIAOの撮影ピーク366 mAを供給できない。容量の数字だけを比較して選べない。

Game Boy Pocket本体の2本の単4電池から分岐する方法も採用しない。撮影ピーク約1.39 Wを3 Vから効率90%で作るだけで、XIAO用として約515 mAが必要になる。これにPocket本体の消費が加わるため、電圧低下、リセット、画面変動、電池寿命の大幅な短縮が予想される。交換式電池を使いたい場合はPocketとは別の電池ボックスと、5 V・1 A以上を出力できる昇圧回路を用意する。

## 電力の比較

Seeed Studioの公称値では、XIAO ESP32S3 SenseのWebカメラ動作はUSB 5 Vで平均約140 mA、撮影ピーク約347 mA、BAT 3.8 Vで平均約155 mA、撮影ピーク約366 mA。カメラ別の表には640×480動作時の最大約0.6 A（OV3660）または約0.65 A（OV2640）も記載されている。

Game Boy Pocket本体の背面定格は3 V、0.7 Wであり、入力電流換算では約233 mA。XIAOのUSB撮影ピークだけでも約1.74 Wで、Pocket本体の入力電力定格0.7 Wを大きく上回る。電圧変換損失とGame Boy自身の消費もあるため、純正Pocketの5 VレールにXIAOを追加する余裕はない。

Pocketの回路図ではリンクポート1番は本体の5 V VDDレールへ接続される。専用の大電流電源出力ではなく、公式リンクケーブルでは1番自体が省略されている。Game Boy本体の動作不安定、画面の濃度変動、リセット、DC/DC回路や保護部品への過負荷を避けるため、ここからXIAOやカメラへ給電しない。必要電流の小さいレベルシフタのHV基準・電源だけを例外とする。

## コンデンサ

コンデンサは不足している平均電力を補えない。例えば347 mAを0.3 V以内の低下で100 ms支えるには、理想計算でも約0.116 F、すなわち116,000 µFが必要になる。一般的な470 µFでは同じ条件を約0.4 msしか支えられない。したがって、コンデンサを追加してGame Boyから給電する方法は採用しない。

XIAOを独立電源で動かす場合、基板上にローカルのデカップリングは実装済み。短いUSBケーブルと安定した1 A以上の電源なら、通常は外付けコンデンサを追加しなくてよい。

自作の電源配線が長い、昇圧モジュールを使う、撮影時にリセットする場合は、次を電源モジュールではなくXIAOの近くへ置く。

- 5 VとGND間に10 µF以上のセラミックまたは低ESRコンデンサ
- 必要に応じて100～470 µF、耐圧6.3 V以上の低ESR電解コンデンサ
- レベルシフタの各電源端子に0.1 µFセラミックコンデンサ

100～470 µFは配線や電源回路による短い電圧低下を緩和する補助であり、電源は単独で0.6 A以上、設計値として1 Aを供給できるものを使う。

## ファームウェアの発熱対策

以前の実装は起動時からカメラを初期化し、Wi-Fiを常時稼働させていた。現在は次の動作へ変更した。

1. 待機中はカメラを初期化せず、Wi-FiをOFFにする。
2. 撮影要求を受けた時だけカメラとWi-Fiを起動する。
3. 通信中は接続安定性を優先し、処理が終わった時点でWi-Fiを完全にOFFにする。
4. Gemini応答の取得後、カメラをdeinitし、Wi-Fiを切断してOFFにする。
5. USBシリアルの5秒ごとの状態表示へESP32-S3内部温度`chip=xx.xC`を追加する。

内部温度はケース表面温度や周囲温度と同じではなく、絶対温度の校正値としてではなく変化を見る目安として使う。撮影終了後も温度が上がり続ける、再起動を繰り返す、触れ続けられないほど熱い場合は給電を止めて配線と電源電圧を確認する。

2026-09-07のUSB給電試験では、待機時の内部温度表示は約51 ℃、20秒のWi-Fi接続試行中は約59 ℃、停止後は約55 ℃へ下がった。この値は電流計による消費電力測定ではなく、ファームウェアの停止処理と温度変化を確認した結果である。当日のアクセスポイント認証がタイムアウトしたため、Gemini応答完了までの温度は未測定。
