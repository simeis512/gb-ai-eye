# XIAO・Game Boy間プロトコル

## 物理層

Game Boyを内蔵クロックのマスター、XIAOをスレーブとして扱う。DMGのクロックは8192 Hz、アイドル時はHigh。XIAOはSCKの下降時に次の送信bitをSINへ出し、上昇時にSOUTを読み取る。各バイトはMSBから送る。

Game Boyリンクポートにはチップセレクトがないため、一般的なCS必須SPIスレーブドライバではなくGPIO割り込みで処理する。16エッジ×約1000バイト/秒なので、ESP32S3で十分処理できる。

## 制御値

| 値 | 名前 | 意味 |
|---|---|---|
| `43` | CAPTURE | Game Boyからの撮影要求 |
| `06` | ACK | 待機中、要求受付、送信完了 |
| `15` | NAK | 設定不足、撮影失敗、API失敗、変換失敗 |
| `17` | BUSY | 撮影またはAI処理中 |
| `80`～`BF` | DATA_HEADER | 下位6 bitが本文長 |

## 応答フレーム

```text
+----------------+-------------------+----------------+
| 80 | length    | text[length]      | xor checksum   |
+----------------+-------------------+----------------+
```

- 本文長は1～63バイト。ヘッダーの下位6 bitをすべて使用する。
- checksumは本文全バイトのXOR。
- 本文は初代ポケモン日本版の表示文字コード。
- 正規化後の表示文字が18文字を超える場合、XIAOが18文字目の後へ2行目移動コード`4F`を挿入する。最大36文字を18文字ずつ2行に表示する。
- 濁音・半濁音は原則として日本版ROMの合成済み1バイト文字へ変換する。AIがUnicodeの基底かな＋結合濁点／半濁点を返した場合も、XIAO上で同じ1文字へ正規化してから文字数と改行位置を計算する。単独記号で表す必要がある場合、初代ポケモンの描画仕様に従い`E5`または`E4`を基底かなより先に置く。
- Game Boy側は受信バッファの前へ`00`、後ろへ`57`を追加する。

## 全二重通信のタイミング

Game Boyの各転送は送信と受信が同時に進む。XIAOは受け取ったバイトを確認してから同じ転送の応答を変えられない。このため、CAPTUREを受信する転送では事前に準備したACKを返す。

```text
Game Boy -> XIAO : 43   00   00   ...  00          00 ... 00  00
XIAO -> Game Boy : 06   17   17   ...  80|length   text...     xor
```

CAPTURE直後の最初の状態確認まで最低1フレーム空ける。本文送信が始まった後も、Game Boy側は各バイトの後に約0.12 msの準備時間を置く。CAPTUREの8 bit目を受信した割り込み内で前回の未送信フレームを破棄し、次の応答を直ちにBUSYへ固定する。これにより連続実行時に前回のDATA_HEADERを新しい結果と誤認しない。新しいセッションは最低4秒BUSYを維持する。

XIAOはSCKのCHANGE割り込みがHigh/Lowで交互になっているか検査する。同じレベルを連続検出した場合は欠落エッジとして現在のバイトを破棄し、3 msを超えるアイドル区間の次のエッジを新しいバイト境界として再同期する。DMGの正常な1バイトは約0.98 msなので、この境界が正常なバイト内へ入ることはない。

## AI出力

`include/app_config.h`の`AI_PROVIDER`でOpenAIとGeminiを選択する。カメラはSVGA（800×600）、JPEG quality 10で撮影する。OpenAIはResponses APIの`gpt-5.6-sol`へJPEGのbase64 data URLを送り、reasoning effortは`none`、画像detailは`high`。Geminiは`gemini-3.8-flash`へJPEGを`inline_data`として送り、thinking levelは`low`。どちらも同じプロンプトで、箱・パッケージと実物の区別、読める固有名の優先、カタカナ表記、36文字以内、改行なしを指定する。

HTTPS接続前にNTPで時刻を同期する。GeminiはGoogle Trust Services Root R1～R4で検証する。OpenAIの配信基盤は接続時期や経路によりGoogle Trust ServicesまたはLet's Encryptの証明書を返すため、GTS Root R1～R4とISRG Root X1/X2の両方を組み込んで検証する。

Wi-Fi接続、時刻同期、HTTPS接続、空応答、15～36文字の範囲外、63バイトの本文枠へ収まらない回答、GB未対応文字、HTTP 408/429/500/502/503/504は、同じ撮影画像を保持したまま最大3回まで再試行する。各HTTPS要求のタイムアウトは25秒で、試行間は1.5秒、3秒と段階的に待つ。再接続時はWi-Fi無線部を停止してからSTAモードを作り直す。

プロンプトから個別の商品名や作品名の例を除き、写真中の文字と図柄だけで固有名を判断するようにしている。AIの回答はエンコーダーと同じ文字表で検査し、未対応文字が一つでもあれば再要求する。3回とも不適合なら表示可能な定型講評へ差し替えるため、未対応文字が`？`として混入しない。

## 実装上の状態

`GameBoyLink`の割り込みは、撮影/API処理とは独立して動く。割り込みがCAPTUREを受けると旧フレームを消してBUSYへ移り、メインループがFreeRTOSの撮影/APIタスクを開始する。完了時にフレーム全体を割り込み側へ一括公開するため、送信途中の本文が書き換わらない。

受信キューがあふれた場合は`queueOverflows`、アイドル後に再同期した場合は`resyncs`、欠落エッジを検出した場合は`edgeFaults`が増える。USBシリアルへ5秒ごとにこれらの統計、受信総数、最終受信値、撮影状態、送信状態を表示する。撮影開始時はセッション番号と旧ストリームの破棄も表示する。
